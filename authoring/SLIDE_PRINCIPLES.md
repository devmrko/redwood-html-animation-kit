# 발표 장표 작성 원칙

제품 비교, 기술 설명, 제안, 교육, 실험 결과, 진행 보고 등 모든 발표의 기획·작성·검수에 적용합니다. 각 장표의 역할에 맞게 사용하고, 발표에 없는 비교·비용·수치를 억지로 추가하지 않습니다. 사실과 수치는 제공된 자료와 확인한 근거에 따릅니다.

## 작성 원칙

### 1. 청중이 알아야 할 결과와 판단을 먼저 보여준다

- 청중이 무엇을 이해하고, 결정하거나 실행해야 하는지부터 정합니다.
- 발표 초반에 핵심 결과·변화·제안과 그 의미를 보여줍니다.
- 비교 발표는 첫 비교 장표부터 대상별 차이가 보여야 합니다. 설명·교육 발표는 먼저 전체 개념이나 도달할 결과를 보여줍니다.

### 2. 만연체를 쓰지 않는다

- 긴 설명문 대신 짧은 문장·수치·표·도식을 씁니다.
- “외부 접근에 대한 제약이 존재함을 확인했습니다”는 “Trial에서 외부 API 차단”으로 줄입니다.
- “처리 시간을 단축할 수 있다는 점을 보여줍니다” 대신, 측정한 경우 “처리 시간 10분에서 3분으로 감소”처럼 결과를 씁니다. 측정값이 없으면 수치를 만들지 않습니다.
- “~할 수 있다는 점을 보여줍니다”, “~를 구분해야 합니다” 같은 우회 표현을 줄이고 주체·행동·결과를 직접 씁니다.

### 3. 제목에 핵심 메시지나 결론을 쓴다

- 본문 장표는 주제명보다 전달할 결론·관계·행동이 드러나는 제목을 씁니다.
- “실험 결과”보다 “캐시 적용 후 응답 시간 감소”, “처리 과정”보다 “등록 후 검토를 거쳐 승인 자료를 보관”처럼 씁니다. 근거보다 강하게 단정하지 않습니다.
- 본문 제목만 순서대로 읽어도 발표의 논리가 이어져야 합니다.
- 표지·목차·간지·부록은 각각 발표 주제·구조·전환·자료 범위를 분명하게 표시합니다.

### 4. 한 장에 핵심 판단이나 메시지 하나를 담는다

- 한 장에서 답할 질문을 하나로 정합니다. 기능·인증·비용 등 서로 다른 판단은 나눕니다.
- 여러 대상을 같은 기준으로 비교하거나, 여러 단계를 하나의 흐름으로 설명하는 것은 하나의 메시지일 수 있습니다.
- 3초 안에 요점이 보이는지 검수합니다. 요점을 파악하려고 긴 문단부터 읽어야 한다면 제목·배치를 고칩니다.

### 5. 핵심 내용을 상세보기로 숨기지 않는다

- 본문에 결론·주요 근거·청중에게 미치는 영향을 표시합니다.
- 상세보기·부록에는 설정 절차, SQL·코드, 전체 로그, 유도 과정, 추가 스크린샷을 둡니다.
- 클릭하지 않아도 핵심을 이해할 수 있어야 합니다. 단계별 효과를 써도 핵심 설명이 별도 상세보기 안에만 있어서는 안 됩니다.

### 6. 주의 문구와 사용 안내가 본문을 차지하지 않게 한다

- “카드를 선택하세요”, 실험 범위나 일반적인 면책 문구를 장마다 반복하지 않습니다.
- 해석에 필요한 조건은 해당 결과 옆에 짧게 붙입니다. 예: “외부 API 차단 — Trial 계정”.
- 시험 환경·평가 방법·공통 전제는 별도 장표나 부록에 모읍니다. 단, 결론을 바꾸는 조건은 본문에도 남깁니다.

### 7. 같은 정보는 같은 위치·같은 기준으로 보여준다

- 반복되는 대상 순서, 항목, 용어, 단위, 상태 표시를 통일합니다.
- 비교는 같은 조건을 기준으로 하고, 조건이 다르면 결과 옆에 표시합니다. 흐름도는 단계·화살표 방향과 범례를 일관되게 씁니다.
- 성공, 계정 제한, 실행 오류, 문서상 미지원, 미시험을 구별합니다. 관측한 사실·해석·예상도 섞지 않습니다.
- 색상과 글자·기호를 함께 사용해 색만으로 의미를 전달하지 않습니다.

### 8. 관계와 근거에 맞는 시각 표현을 우선한다

- 항목·지원 여부·결과 비교는 표, 과정·구조·원인 관계는 도식, 같은 단위의 크기·변화는 그래프로 보여줍니다.
- 핵심 수치는 크게 표시하고, 짧은 문장으로 의미를 보완합니다. 표나 그림이 이해를 돕지 않는 경우에는 짧은 문장을 사용합니다.
- 장식과 반복 설명을 줄이고 판단과 이해에 필요한 정보를 남깁니다.

### 9. 비용·시간·자원·제약은 구체적인 항목으로 설명한다

- 선택이나 실행에 영향을 주는 비용, 소요 시간, 인력·자원, 운영 부담과 제약을 구체적으로 씁니다.
- 비용을 다룰 때는 초기·실행·유지 비용을 구분하고, 필요에 따라 API·SQL·LLM·검색 유지·별도 서버 등 구성 항목으로 나눕니다. 실행 시 비용과 켜 두는 동안의 비용도 구분합니다.
- 동일 작업·시간·단위로 맞출 수 있는 항목은 수치로 비교합니다. 단위가 다르면 구조와 환산 조건을 보여줍니다.
- “직접 비교 불가”로 끝내지 않습니다. 환산에 필요한 조건·부족한 자료·판단 가능한 범위를 표시합니다. 근거가 없는 값을 추정치나 확정값으로 만들지 않습니다.

### 10. 큰 글자로 읽히는 분량만 넣는다

- 글자를 줄여 내용을 밀어 넣지 않습니다. 넘치면 문구를 정리하거나 장표를 나눕니다.
- 발표 화면에서 읽히는 크기와 여백을 확보합니다. 제공된 템플릿의 글꼴을 유지하고 크기·굵기로 위계를 만듭니다.
- 간결함과 큰 글자를 우선하되 모든 발표를 특정 장수로 제한하지 않습니다.

### 11. 증거 화면과 시각 자료는 주장에 붙여 보여준다

- 중요한 성공·실패 화면, 사진, 그래프는 관련 주장 옆에 배치하고 핵심 부분을 강조합니다.
- 전체 원본은 확대하거나 부록에서 볼 수 있게 연결합니다. 근거를 확인할 수 없을 정도로 자르거나 왜곡하지 않습니다.
- 제품 화면, 사후 재열람 화면, 저장 로그 뷰어 등 증거의 종류를 짧게 표시합니다. 재현·모의 화면은 실제 실행 화면과 구별합니다.
- 출처·시점·시험 조건이 해석에 필요하면 해당 자료 옆에 간결하게 표시합니다.

### 12. 전체 그림에서 시작해 필요한 상세로 내려간다

- 전체 결론·개념·제안·흐름을 먼저 보여주고, 항목별 설명, 대표 근거, 구현·로그 순으로 깊이를 더합니다.
- 첫 내용 장표를 메뉴 카드만으로 채우지 않습니다. 큰 영역에는 발표의 핵심 내용 자체가 보여야 합니다.
- 비교는 전체 차이와 선택 기준, 교육은 개념과 학습 목표, 제안은 해결할 문제와 제안의 효과, 보고는 결과와 다음 행동을 먼저 제시합니다. 효과를 예상한 경우에는 예상임을 표시합니다.

## 장표 통과 기준

- 제목만 읽어도 핵심 메시지와 발표의 흐름을 알 수 있는가?
- 상세보기 버튼을 누르지 않아도 중요한 내용·관계·차이가 보이는가?
- 주장을 뒷받침하는 수치·표·도식·실제 화면 등 적절한 근거가 있는가?
- 조건·비용·제약이 이해·선택·다음 행동에 어떤 영향을 주는지 알 수 있는가?
- 실제 발표 화면에서 글자와 시각 자료가 읽히며 요점을 빠르게 파악할 수 있는가?

표지·목차·간지·마지막 장에는 그 역할에 맞는 기준을 적용합니다. 모든 장표에 수치나 증거 화면을 강제로 넣지 않습니다. 발표 전체를 검수할 때는 제목만 이어 읽고, 실제 발표 크기로 모든 장표를 확인합니다.
