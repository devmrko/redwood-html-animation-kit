# 시나리오와 사진으로 장표 만들기

사용자는 시나리오와 사진으로 발표 정보와 기본 초안을 작성한다. 제작용 프로젝트를 내보내 Codex·Claude가 본문 페이지를 제작하고 검수한 뒤 발표·영상·SRT로 사용한다. 현재 제작 흐름과 계약은 [Codex·Claude 페이지 제작 설계](./agent-authoring-design.md)를 따른다. 기존 13개 예제는 구성과 효과를 비교하는 샘플이며 새 문서의 내용에 종속되지 않는다.

## 모듈과 계약

- `presentation-document`: 버전 1 문서·이미지 자산 계약, 검증, 시나리오 분할과 기본 구성. DOM과 서버에 의존하지 않는 순수 모듈이다. 문서는 표지·섹션·본문·사진·단계·비교·마지막 장 레이아웃을 선택한다. 사용자 텍스트를 HTML 코드로 해석하지 않는다.
- `presentation-document-view`: 검증된 문서와 자산, 테마를 받아 DOM과 기존 PresentationTimeline 재생기를 만든다. 섹션·소주제 표시는 본문 머리말이며 단계형 레이아웃은 도식과 현재 설명을 함께 강조한다. 공통 모듈에 Oracle 자산 경로를 넣지 않는다.
- `presentation-project-store`: IndexedDB에 문서와 이미지 자산을 저장한다. 선택형 transport의 publish/retrieve를 주입받는다. 앱은 JSON 파일 저장·불러오기로 다른 기기에 프로젝트를 전달할 수 있다. 앱 소유 `project-store.js`는 `/api/projects/<UUID>`에 연결하고 로컬 서버의 임시 저장소를 통해 다른 브라우저 프로필의 발표 창에 같은 프로젝트를 제공한다. 서버 재시작 시 브라우저 저장본을 다시 publish할 수 있다. 서버 임시 저장은 내구성 있는 저장소가 아니다.
- `builder.html`·`builder.js`: 입력 → 장표 목록·선택한 장표 편집 → 미리보기·발표·내보내기를 연결한다. 이미지 선택·저장 실패를 표시한다.
- `deck.html`·`deck.js`: Reveal.js, 기존 발표 창/발표자 보기 및 export 어댑터를 연결한다. `export.html?project=<UUID>`는 생성된 장표를 같은 자막·시간·녹화 모듈로 처리한다.
- Python LLM 어댑터는 기존 OpenAI 호환 연결을 재사용한다. 사용자가 요청한 경우 시나리오와 사진 파일명만 제공자에 전달한다. 사진 내용의 인식이나 OCR은 포함하지 않는다. 기본 생성은 로컬에서 수행한다.

## 입력·표현·시간

미리보기 보완: 편집 화면은 별도 deck 페이지를 iframe으로 재요청하지 않고 같은 JSON을 공통 렌더러에 직접 전달한다. 선택한 한 장을 표시할 때 원래 페이지 번호와 전체 장수를 render options로 제공한다. 렌더링과 내용 확인이 끝난 뒤 완료 상태를 표시하며, 실패 시 빈 캔버스 대신 오류를 표시한다.

템플릿 보완: 앱의 `template-theme.js`와 `templates/legacy/redwood-2019.css`가 사용자 POTX의 표지 6, 목차 강조 34~35, 단 구성 19~21, 마지막 장 46의 좌표·배경·장식을 제공한다. 공통 렌더러는 테마와 섹션 목록을 주입받으며 JSON은 콘텐츠를 채운다. 생성 시 간지를 보장하고, 표지는 패턴 테두리·회색 패널·좌상단 로고, 간지는 전체 목차와 현재 항목 강조, 마지막 장은 50:50 분할을 적용한다. 원본은 PowerPoint에서 직접 확인했다. 사용자 보완 요청에 따라 한글은 표지·간지·본문·마지막 장 모두 한 글꼴 집합을 사용한다.

시나리오는 Markdown 제목과 목록 또는 빈 줄로 나눈 문단을 받는다. 첫 `#` 제목은 발표 제목, `##`는 장표 제목, `###`는 하위 장표로 해석한다. 숫자 목록은 단계, 비교 표현은 비교 레이아웃 후보로 분류한다. 사진은 입력 순서로 본문 장표에 배치하고 남는 사진은 사진 장표로 추가한다. 사용자가 편집 화면에서 배치를 바꿀 수 있다. 원문은 프로젝트에 보관한다.

생성된 문서는 JSON으로 검증한 뒤 렌더링한다. 이미지 참조는 프로젝트 내부 ID만 사용한다. PNG/JPEG/WebP의 MIME·파일 시그니처를 확인하며 SVG/원격 URL/HTML은 이미지 입력으로 받지 않는다. 문서 최대 60장, 이미지 최대 20개·각 5MB·합계 25MB, 시나리오 3만 자로 제한한다. 저장소 용량 부족·손상된 JSON은 기존 프로젝트를 덮어쓰지 않는다.

요소별 등장 시간은 실제 재생기에 연결하고 본문·단계·애니메이션에 따른 최소 시간과 자막 읽기 시간을 기존 공통 모듈에서 계산한다. 단계별 수동 이동과 자동 재생을 모두 지원하며 영상은 자동 재생한다. 프로젝트별 자막 편집 설정은 분리한다.

## 검증 기준

시나리오·사진 → 검증된 문서 → 동일 문서의 장표 메타데이터·자막 계획·SRT 연결을 검증한다. 입력 검증은 사용자 텍스트의 코드 실행, 외부 이미지 참조, 중복 ID·잘못된 참조를 거부해야 한다. 브라우저에서 사진 포함 생성·선택 편집·단계 이동·새로고침 후 복원·발표/내보내기 링크를 확인한다. 실제 검증 범위와 제약은 완료 시 갱신한다.

## 확인한 동작과 제약

2026-11-17 Chrome에서 사진 포함 4장 생성, 단계 도식·사진 표시, 단계별 수동 이동, 새로고침 복원, JSON 저장을 확인했다. 내려받은 JSON의 제목과 문서 ID를 바꿔 다시 불러왔을 때 편집 화면과 실제 장표에 바뀐 제목이 표시되었다. Chrome에서 만든 문서를 Edge 앱 모드 발표 창으로 열어 같은 JSON이 표시됨을 확인했다. 생성 장표를 기존 export 화면으로 연결해 실제 SRT를 다운로드하고, 자막을 표시한 3.1초 H.264 MP4(1920×1080, 30fps)를 생성해 프레임을 확인했다. 저비용 OpenRouter 모델로 장표 구성 요청도 실제 실행했다.

기본 초안은 문단·목록 기준으로 분할하며 사진의 의미를 추론하지 않는다. 이 기본 초안의 레이아웃 종류는 제한되어 있으나, 실제 제작 페이지는 별도 JS 모듈을 주입하므로 고정 구성으로 제한하지 않는다. 앱에서 외부 LLM API로 본문 코드를 자동 생성하지 않는다. Codex·Claude가 템플릿과 공통 인터페이스를 따라 제작·검수한다. 자막 읽기 시간은 추정치이며 음성 합성은 포함하지 않는다.
