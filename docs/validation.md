## 알파 2 · 선택형 자막과 포인터 제외 · 2026-11-19

Chrome의 실제 내보내기 UI에서 차트·마지막 장 2개를 선택하고 **MP4 선택형 자막 + SRT 파일**로 12.1초를 녹화했습니다. FFprobe로 H.264·1920×1080·30fps와 `mov_text` 한글 자막 트랙을 확인했습니다. 별도 다운로드 SRT와 작업 SRT는 동일하며, MP4에서 추출한 자막도 0–8.3초/8.3–12.1초의 문구·시각이 일치합니다. 원본 영상 프레임에는 자막이 구워지지 않았습니다. 재생기별 자막 선택 UI를 모두 검수한 결과는 아닙니다.

공통 녹화 모듈에서 포인터 제외를 최초 요청과 트랙 설정에 적용합니다. [Screen Capture의 cursor 제약](https://w3c.github.io/mediacapture-screen-share/#cursorcaptureconstraint)에 따른 요청이며 지원하지 않는 브라우저에서는 녹화를 계속합니다. 이번 Chrome의 4초 추출 프레임에서는 이전 검증 영상에 있던 포인터가 보이지 않았습니다. 모든 브라우저·운영체제에서 포인터가 제거된다고 보장하지 않습니다. 로컬 증거는 `dist/export-review-r2/soft-review.mp4`, `soft-ui.srt`, `soft-job.srt`, `soft-embedded.srt`, `soft-report.json`, `soft-frame.jpg`입니다.

README의 저장소 편집 화면과 더블클릭용 발표 ZIP 설명을 구분하고, OCI 컴파트먼트 이름 설정을 안내에 반영했습니다. 실제 초보 사용자에 의한 독립 사용성 시험은 아직 진행하지 않았습니다. 파일 직접 실행·Windows 검증도 미완료 상태로 릴리스에 명시합니다.

## PPT·MP4·SRT와 응답 연결 중단 · 2026-11-19

공개 사진·증거·표·3초 합성 영상·막대 차트를 포함한 6장 자료를 제작 폴더와 실행본 ZIP으로 만들었습니다. 실제 내보내기 화면에서 PPT 두 방식과 SRT를 다운로드하고, 보이는 Chrome 탭만 공유해 자막을 표시한 MP4를 녹화·변환했습니다. 외부 모델 호출·개인 장표 사용은 없습니다. 재현 자료는 `python3 tests/build_offline_fixture.py --output dist/export-review --export-review`로 만들 수 있습니다.

**PPT:** Mac PowerPoint에서 화면 유지형과 편집형을 직접 열었습니다. 편집형의 표·사진·영상 정지 화면·차트 값을 확인했으며 6장 모두 발표 노트가 들어 있습니다. XML에서 실제 표 1개, 차트 장표의 네이티브 도형/텍스트 18개, Oracle Sans Tab/Apple SD Gothic Neo 지정도 확인했습니다. 편집형 차트는 PowerPoint 차트 데이터 객체가 아니라 편집 가능한 도형/텍스트입니다. Windows 글꼴 대체와 모든 임의 장표의 동일 배치를 보장한 검사는 아닙니다.

화면 유지형에서는 SVG의 테마 색·보조선이 빠지는 오류를 발견했습니다. PNG 렌더러가 바깥 HTML의 CSS 속성 목록을 캐시해 장표에만 정의한 CSS 변수가 SVG에 전달되지 않는 경로였습니다. 캡처 동안 SVG의 계산된 색을 명시하고 완료·실패 후 원래 속성·inline style·우선순위를 복원하도록 수정했습니다. 수정본을 다시 다운로드해 PowerPoint에서 실제 색과 보조선을 확인했습니다. 성공/실패 시 원본 복원도 단위 검사합니다.

**MP4·SRT:** 실제 H.264, 1920×1080, 30fps, 무음, 49.600초, 1,382,146바이트입니다. 공통 계획은 49.6012초로 한 프레임 이내 차이이며 별도 SRT와 영상 작업의 SRT는 바이트까지 일치합니다. 긴 자막 장표는 기본 6.5초에서 18.499초로 늘어났습니다. 사진→표/영상은 약 19.002초, 표/영상→차트는 약 37.501초에 전환하도록 계획됐고 18.8/19.4/27.9/37.9/46.3초 프레임에서 전환 전후·긴 자막·영상 끝 화면·차트·마지막 장을 확인했습니다. 모든 전환의 정확한 프레임을 전수 측정한 것은 아닙니다. 녹화에는 마우스 포인터가 포함됐습니다. 선택형 자막·오디오 포함·다른 브라우저 녹화는 이번 확인 범위에서 제외합니다.

**AI 응답 중단:** 실제 HTTP 연결을 생성 응답 직전 또는 적용 완료 뒤 끊는 검증 서버를 추가했습니다. 모델·썸네일만 합성이며 편집 UI·HTTP·로컬 Git은 실제 코드입니다.

| 중단 위치 | Chrome과 HTTP 검사 결과 |
| --- | --- |
| 생성 완료 뒤 응답 전 | 적용 비활성·재요청 가능·요청문 유지. 적용 0회·원본 버전 1개·원본 제목/대본 유지 |
| 적용 완료 뒤 응답 전 | 적용 여부 불명 안내와 최신 버전 버튼. 자동 재적용 없이 최신 조회로 변경 제목 확인. 적용 1회·버전 2개·대본 유지 |
| 응답이 끊긴 적용의 복원 | HTTP 검사에서 확인한 최신 버전을 기준으로 원본 복원, 새 버전 3개. 동일 적용을 재전송하지 않음 |

연결 실패 때 브라우저의 `Failed to fetch`를 그대로 표시하던 안내도 한국어로 보완했습니다. 생성 응답 자체를 받지 못한 경우 클라이언트는 편집안 토큰을 모르므로 서버에 미적용 대기안 1개가 남을 수 있습니다. 이 대기안이 원본에 자동 적용되지는 않습니다. 실제 프로세스 강제 종료·디스크 장애·OCI/OpenAI 제공자 내부의 전송 중단까지 재현한 것은 아닙니다.

**ZIP:** 2,822,170바이트·198개 파일의 ZIP만 푼 정적 폴더에서 본문·검색 후 차트 이동·640×360 로컬 영상 재생·발표자 창의 다음 장표/대본 동기화를 확인했습니다. `.env`와 로컬 AI 이력은 포함되지 않았습니다. 이 검사는 HTTP에서 내장 실행본을 확인한 결과이며, 파일 직접 실행의 통과를 뜻하지 않습니다. 파일 더블클릭은 이 환경의 브라우저 보안 제한으로 확인하지 못했고 Windows도 미검증입니다.

자동 검사 **120개(Node 48·Python 72)**, TypeScript 컴파일·배포 동기화, 정적 검사를 통과했습니다. 로컬 증거는 `dist/export-review-r2/`의 PPT·SRT·계획·`timing-report.json`·MP4 추출 프레임·PowerPoint 화면·연결 중단 결과입니다. 검증용 산출물은 Git에 포함하지 않습니다.

## 화면 크기별 공통 구성요소 · 2026-11-19

공통 차트를 장표 본문 전체 너비로 넣으면 SVG의 원래 가로세로 비율에 따라 높이가 560px 본문보다 커져 아래쪽이 잘렸습니다. 공통 발표 CSS에서 차트 컨테이너의 높이를 주어진 영역으로 제한하고 SVG를 그 영역에 맞췄습니다. SVG viewBox의 비율은 유지하며 축·수치·범례를 잘라 숨기는 방식은 사용하지 않습니다. 발표 밖의 일반 차트 부품 크기는 바꾸지 않았습니다.

`tests/browser/layout.html`은 실제 공통 렌더러·차트·표·영상·템플릿·장표 맞춤 모듈과 실제 발표 도구 모음 HTML/CSS를 사용합니다. Chrome의 iframe 표시 영역을 다음 크기로 바꿔 검사했습니다. 바깥 브라우저 창 크기를 160번 바꾸거나 실제 모바일 기기로 실행한 검사는 아닙니다.

- 크기: 1920×1080, 1366×768, 1024×600, 768×1024, 390×844
- 테마: 밝게·어둡게
- 모드: 일반 화면·청중 화면의 CSS 배치
- 구성: 표, 공개 사진, 막대·선·도넛 차트, 표와 영상 1개/2개, 영상만 4개

수정 전 **100/160**, 수정 후 **160/160** 조합이 통과했습니다. 수정 전 실패 60개는 차트 3종의 본문 영역 이탈입니다. 검사한 항목은 장표 비율·화면 내 배치, 가로 스크롤, 도구 모음 줄바꿈과 겹침, 제목/본문 경계, 구성요소 경계·빈 크기, 표/설명 텍스트 넘침, 영상 비율·설명 겹침과 640×360 합성 MP4의 메타데이터 읽기입니다. 작은 화면에서도 발표 글자가 충분히 읽힌다는 평가로 해석하지 않습니다.

추가로 기존 실제 브라우저 효과 **33/33**, 표 **4/4**, `npm test` **118개(Node 47·Python 71)**, `node scripts/check.mjs`를 확인했습니다. 로컬 결과는 `dist/layout/before.json`, `after.json`, 화면은 `chart.jpg`, `video.jpg`에 있습니다. 이번 검증은 HTTP·공통 부품의 크기 검사이며 실제 파일 더블클릭, Windows, Reveal 배치, 팝업 연결, 사용자 장표 전체, PPT/MP4/SRT 내보내기와 영상 재생 동기화는 다시 검사하지 않았습니다.

OCI 기본값은 `.env`에서 읽으며 컴파트먼트 이름의 정확한 단일 활성 항목을 IAM으로 조회합니다. 이름이 없거나 중복되면 거절하며 OCID 직접 설정도 유지합니다. 실제 서울 리전과 사용자 지정 컴파트먼트 조회를 확인했습니다. 목록 응답이 큰 계정에서도 모델 응답 크기 제한 때문에 실패하지 않도록 조회 JSON 처리를 분리했습니다. 계정 이름·OCID·모델 OCID와 로컬 `.env`는 저장소에 포함하지 않습니다. 다른 리전으로 자동 전환하거나 클라우드 리소스를 생성하지 않았습니다.

## AI 편집 · 취소와 원본 변경 충돌 · 2026-11-19

적용 전 캡처를 기다리는 중 편집 패널을 닫아도 적용이 이어질 수 있던 경로를 차단했습니다. 미리보기에서 확인한 같은 편집안이 남아 있는지 적용 요청 직전에 다시 확인합니다. 취소한 토큰은 서버에서도 폐기하고, 저장 요청이 시작된 후에는 결과가 올 때까지 패널의 닫기·Escape를 막습니다. 브라우저 종료나 이미 시작한 외부 모델 호출을 취소하는 기능은 아닙니다.

외부 JSON을 아직 조회하지 않았거나 파일 수정 시각이 유지된 경우에도 생성·적용·복원 경계에서 현재 내용을 검사합니다. 초기 Git 이력을 만들 때 브라우저 자료로 다른 원본 파일을 덮어쓰는 것도 거절합니다. 충돌 뒤에는 편집안을 폐기하고 최신 버전을 다시 불러오도록 했습니다. 실패 시 요청문을 유지하며, 저장 응답을 확인하지 못한 편집안을 자동 재적용하지 않습니다. 이 검사는 외부 편집기와 파일 쓰기를 하나의 트랜잭션으로 잠그는 기능은 아닙니다.

`tests/serve_ai_editor_fixture.py`에서 실제 편집 UI·HTTP·임시 Git을 사용했습니다. 모델 응답·캡처 PNG만 합성이고 외부 모델 호출·개인 자료 사용은 없습니다. Chrome에서 확인한 결과는 다음과 같습니다.

| 시나리오 | 확인 결과 |
| --- | --- |

동일한 7종 요청을 OpenAI 호환 API에도 실행했습니다. `openai/gpt-4.1-nano`는 보완 후 재시험에서도 0/7, `openai/gpt-4.1-mini`는 1/7(선 차트)만 형식 검증을 통과했습니다. 나머지는 금지 태그·속성·잘못된 효과 형식 등으로 거절됐고 적용하지 않았습니다. Codex CLI는 7/7 적용됐습니다. 이 수치는 이번 요청 묶음의 결과이며 일반적인 모델 성능 순위가 아닙니다. 작은 모델의 자유 화면 생성은 아직 안정적이라고 볼 수 없습니다. 보완 요청은 한 번으로 제한하고, 다시 실패하면 다른 모델/프로그램을 선택하도록 안내합니다.

재검사는 서버 실행 후 `/tests/browser/smoke.html`에서 **검사 실행**을 누릅니다. `?project=<AI 프로젝트 ID>`를 붙이면 해당 장표의 양쪽 테마 검사도 포함합니다. 결과 JSON을 저장할 수 있습니다. 실제 모델 생성 시험은 `python3 scripts/smoke_visual_scenarios.py --origin http://127.0.0.1:4176 --provider cli --tool codex`로 실행합니다. `--provider openai --model <모델>`도 지원하며 API 요금이 발생할 수 있어 `npm test`에는 포함하지 않습니다.

추가로 출력 예시와 효과 네 필드 제한을 요청에 포함해 nano를 같은 7종으로 재시험했습니다. 막대 차트만 적용돼 1/7이었고 나머지는 거절했습니다. 자유 화면 생성이 안정화됐다고 보지 않습니다. Codex로 생성한 시각 구성 7종의 자료는 9장·107.3초 MP4로 실제 녹화·변환했고 H.264·1920×1080·30fps를 확인했습니다.

### 이 키트로 제작한 사용법 영상

`examples/usage-demo/`의 11장·본문 9개를 같은 렌더러와 영상 내보내기로 제작했습니다. 실제 시나리오 입력·초안 편집·AI 요청·발표자·자막 설정 화면을 캡처해 포함했습니다. 표와 SVG 차트는 공통 Redwood 디자인을 사용합니다.

- Chrome에서 본문 9개×양쪽 테마 18/18, 기존 효과 33/33 검사 통과. 모든 장표를 화면으로 확인했고 마지막 장의 긴 제목과 부제·발표자 겹침은 제목을 줄여 수정했습니다.
- 편집 화면에서 AI 작성 본문을 불러오지 않아 미리보기가 실패하던 문제를 발표 화면과 같은 로더로 수정했습니다. 기존 AI 사진 장표를 편집 화면에서 다시 열어 실제 사진과 불러오기 완료 메시지를 확인했습니다. 오류 뒤 새 문서에서 초안 버튼이 비활성으로 남는 상태도 초기화합니다.
- 최종 11장 영상을 현재 공개 데모 탭으로 녹화·변환했습니다. 실제 MP4는 H.264·1920×1080·30fps·194.966초·3,719,165바이트입니다. 7초·90초·191초 프레임의 표지·어두운 표/차트·마지막 장과 한글 자막을 확인했습니다.
- SRT 34개 자막과 0–194.947초 타임코드를 확인했습니다. 무음 영상이며 음성 합성은 사용하지 않았습니다. `watch.html`은 MP4 재생·단계 목차·SRT·수정용 ZIP 다운로드를 제공합니다.
- `scripts/build_usage_demo.py`로 JSON·사진·선언형 본문·발표용 HTML을 포함한 ZIP을 생성했습니다. 파일 더블클릭 실행 자체는 이번에도 확인하지 못했습니다.

README의 기존 GIF 미리보기를 사용법 MP4 표지·영상·SRT 링크로 교체했습니다. MP4·표지·SRT를 공개 `assets`에 포함했고 원본 출력 파일과 동일한지 확인했습니다. 새 연결은 설치된 Codex를 우선 선택하며 저장한 선택은 유지합니다. Chrome의 기존 nano 선택에서 **기본 연결로 변경**을 눌러 Codex·모델 칸 비움으로 바뀌고 새로고침 후에도 유지되는 것을 확인했습니다. API의 `.env` 모델은 바꾸지 않았고, 새 모델의 추가 생성 시험은 하지 않았습니다. 기존 7종 시험의 Codex 호출과 같은 CLI 기본 모델 선택을 사용합니다.

일반 새로고침으로 빈 화면이 계속되면 Chrome에서 `Cmd+Shift+R`(Windows: `Ctrl+Shift+R`)로 기존 모듈 캐시를 한 번 갱신하세요. 서버 정적 응답은 이후 `no-store`로 전달합니다. 4190은 Safari에서 차단되므로 서버가 이 포트 지정을 거절하도록 했습니다.

AI 생성 결과의 내용·표현 품질은 모델에 따라 달라집니다. 검증에 실패한 편집안은 저장하지 않으며, 실제 적용 전에는 변경 미리보기에서 내용과 화면을 확인해야 합니다. 파일을 더블클릭한 경우와 Windows 시작 파일, OCI 실제 모델 호출은 이번 실화면 시험에 포함하지 못했습니다. 편집형 PPT의 실제 PowerPoint 앱 편집·동영상 오디오 포함·YouTube 재생도 이번 확인 범위에 포함하지 않습니다.

이전 검사에서 확인한 Mac 시작 파일의 공백 경로 실행·종료 정리, Codex 목차·자막 생성, 독립 HTML의 HTTP→Python 연결, 800/640px 배치는 2026-11-18 검증 결과입니다. 이번 변경 후 모든 항목을 같은 범위로 다시 시험한 것은 아닙니다.
