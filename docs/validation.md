## 비교 발표 업데이트 피드백 · 공통 표 컴포넌트 · 2026-11-19

소비 프로젝트 `dataplatform_comparison/docs/52-kit-update-20261119.md`와 그 프로젝트의 `presentation/qa/offline/verification.json`, `presentation/qa/layout-audit/results.json`, 실제 비교표 CSS를 읽었습니다. 해당 문서는 `245e920`을 적용한 비교 발표 51장의 별도 검증 기록입니다. JSON에는 file 실행의 오류·네트워크 요청·배치 실패가 없고 검색·증거·동영상·발표자 연결이 통과한 것으로 기록돼 있습니다. **이번 키트의 새 코드 전체를 파일로 다시 검증했다는 근거로 사용하지 않습니다.** 다른 저장소의 코드와 자료는 수정하지 않았습니다.

공통 키트에서도 확인한 두 원인을 보완했습니다.

- 셀의 `padding:18px 22px!important`가 페이지별 여백을 덮어쓰고 있었습니다. 기본 여백은 유지하며 `rf-comparison-table--compact` 클래스로 세로/가로 10px/16px를 선택하도록 했습니다. 28px 글자는 줄이지 않습니다. 공통 HTML 생성기의 `density` 옵션과 선언형 속성, CSS 여백 변수를 연결했습니다.
- `data-tone`과 `data-status`의 차이로 상태 색이 사라질 수 있었습니다. 같은 상태 값이면 같은 테마 색을 사용하며 두 속성이 같이 있으면 `data-status`가 우선합니다. AI 입력 검사도 허용된 여백·상태 옵션만 통과시킵니다. 임의 실행 속성은 추가하지 않았습니다.

실제 Chrome의 `tests/browser/smoke.html`에서 기존 효과 **33/33**, 표 **4/4(밝게/어둡게 × 기본/작은 여백)**를 통과했습니다. 계산된 글자 크기·셀 여백, 이전/현재 상태 색 일치, 성공·조건부·오류 구분, 충돌 시 우선순위와 작은 여백 표의 하단 버튼 비침범을 검사했습니다. 화면 증거는 로컬 `dist/offline-reconnect/table-components.jpg`입니다. 이번 변경 후 PPT 앱과 파일 직접 실행을 추가로 확인하지는 않았습니다.

자동 검사 **106개(Node 46개·Python 60개)**와 TypeScript 컴파일·배포 동기화, 정적 검사(13장·33효과·73개 연결 파일)를 통과했습니다.

## 알파 이후 · 창 재연결과 작은 화면 · 2026-11-19

발표자 창 연결을 공통 `createPresentationPeerSession`으로 옮겼습니다. 같은 발표 세션의 등록 요청을 주기적으로 확인하며, 프로젝트·연결 토큰·발신 창·출처를 검사합니다. 어느 쪽을 새로고침해도 다시 등록할 수 있고, 닫힌 창에는 조작을 보내지 않습니다. 조작 버튼에서 열었던 창의 참조와 안정된 창 이름을 사용해 중복 창 생성을 줄입니다. 현재 장표 ID를 URL에 반영해 새로고침 때 표지로 돌아가던 동작도 바꿨습니다. 청중 창의 새로고침은 해당 장표의 재생을 다시 시작하며, 새로고침 이전의 재생 시간을 복구하는 기능은 아닙니다.

공개 5장 자료를 새 코드로 ZIP 생성·추출한 뒤 `dist/offline-reconnect/release/`만 제공하는 정적 서버에서 실제 Chrome을 확인했습니다.

- 표지 → 간지 → 사진 장표로 이동하자 청중·발표자 양쪽 URL과 본문·대본이 3번째 장표로 갱신됐습니다.
- 청중 창에서 `Cmd+R`로 다시 로드한 뒤 **발표자 보기**를 눌렀습니다. 기존 발표자 창의 같은 실행 토큰을 유지했고, 해당 장표와 새 재생 위치를 계속 표시했습니다.
- Chrome 200% 확대에서 도구 모음이 줄바꿈되고 미리보기 아래에 스크롤 가능한 대본이 배치됐습니다. 겹침이 없는 것을 화면으로 확인한 뒤 100%로 복원했습니다. 화면 증거는 로컬 `dist/offline-reconnect/speaker-200.jpg`입니다.
- 청중 창을 닫자 발표자 창에 종료 안내가 나타났습니다. 그 창의 다음 버튼으로 3번째 사진 장표에서 4번째 표·영상 장표로 이동했고, 대본과 영상도 표시됐습니다.
- Node에서는 실제 공통 세션 모듈로 양방향 메시지를 교환해 양쪽의 재생성·재등록, 잘못된 토큰/창/상태 거절, 창 종료와 정리 후 타이머 제거를 HTTP/file 모델에서 확인했습니다. 실제 파일 브라우저 실행과 구분합니다. 안정된 창 이름을 사용해도 준비 확인 토큰은 새로 생성되는지 검사했습니다.

파일 더블클릭과 Windows, 새 코드의 Edge/Safari 실화면 검수는 남아 있습니다. 파일 실행의 보안 제한을 우회하지 않았습니다. 이전 절의 Edge 검증은 이전 코드에서 확인한 범위입니다.

## 알파 이후 · 배포본 실행 안정화 · 2026-11-19

`v0.1.0-alpha.1` 이후 첫 과제를 진행했습니다. [개선 순서와 재현 절차](alpha-roadmap.md)에 완료 기준과 남은 환경을 정리했습니다. 이 단계 전체가 완료됐다는 뜻은 아닙니다.

자동 검사 **101개(Node 42개·Python 59개)**, TypeScript 컴파일·배포 파일 동기화, 정적 검사(13장·33효과·72개 연결 파일)를 통과했습니다.

- 오프라인 HTML의 **발표 시작**도 별도 청중 창을 엽니다. 공통 창 제어가 새 창의 준비 응답을 확인한 뒤 성공을 표시합니다. 발표자 창도 같은 검사를 사용하며 차단·초기화 실패·준비 전 종료·시간 초과를 성공으로 표시하지 않습니다.
- 발표자 동기화에서 같은 장표를 매번 끝까지 초기화하지 않고 재생 위치만 갱신합니다. 재생/일시정지 표시도 청중 창의 상태를 따릅니다. 파일 메시지는 opaque origin을 기준으로 검사하고 실제 연결 창의 identity도 확인합니다.
- `Cmd+R`이 장표 다시 재생으로 처리되는 것을 실제 Chrome에서 발견했습니다. 공통 키 판별 함수가 브라우저 단축키·입력 조합을 제외하도록 수정했고, 수정 후 두 번째 장표에서 `Cmd+R`로 브라우저가 다시 로드되는 것을 확인했습니다.
- 공개 템플릿 사진·증거 이미지·합성 3초 MP4를 포함한 5장 자료를 **실제 완성본 ZIP 함수로 생성하고 ZIP만 따로 풀었습니다**. 검증 서버는 그 폴더의 정적 파일만 제공했으며 편집 API는 실행하지 않았습니다. 외부 모델 호출은 하지 않았습니다.

## 폴더 정리 · 2026-11-19

화면을 `app/`, 애니메이션·부품을 `examples/`, 자동·브라우저 검사를 `tests/`로 분리했습니다. README 영상은 `docs/media/`, 이전 스타일은 `templates/legacy/`, 새 생성물은 Git에서 제외한 `dist/`에 둡니다. 실행에 쓰지 않는 두 GIF는 현재 파일 트리에서 제거했으며 Git 이력은 재작성하지 않았습니다.

- Node 38개·Python 59개, 합계 **97개** 통과. HTML의 base 경로·inline script·추가 진입점까지 검사하는 정적 검사 통과.
- 기존 `/deck.html` 요청이 프로젝트·장표 쿼리를 보존해 `/app/deck.html`로 연결되는 HTTP 검사를 추가했습니다. 실제 Chrome에서도 이전 주소로 열고 새로고침한 뒤 장표와 프로젝트 ID가 유지되는 것을 확인했습니다.
- HTML base와 Reveal의 해시 쓰기가 프로젝트 쿼리를 지우는 문제를 발견해 호스트에서 절대 URL로 해시를 갱신하도록 수정했습니다. Node 검사에서 HTTP 경로·쿼리와 파일 URL 보존을 확인했습니다. 실제 파일 더블클릭 동작을 검증했다는 뜻은 아닙니다.
- 새 `tests/browser/smoke.html`에서 실제 효과 33/33과 사용법 본문 양쪽 테마 18/18 통과.
- 제작용 ZIP을 임시 폴더에 풀어 **그 ZIP의 파일만으로** 정적 검사·카탈로그 재현 검사를 통과했습니다. 개발 테스트·유료 모델 시험·불완전한 별도 예제가 제외되고 package 명령도 포함된 도구만 가리키는지 확인했습니다.
- 사용법 ZIP을 별도 폴더에 풀고 별도 임시 포트의 Python으로 실행했습니다. Chrome에서 본문 표시, 발표→편집→내보내기 연결, 11장·노트 11개 PPT와 34개 자막 SRT의 실제 다운로드를 확인했습니다. 독립 샘플의 차트 화면과 마지막 장, 청중용 발표 창도 확인했습니다.

이번 폴더 정리 후 MP4를 새로 녹화하거나 PowerPoint 앱에서 편집하지는 않았습니다. README 영상 파일은 기존에 검증한 MP4를 경로만 옮겼습니다. 파일 더블클릭과 Windows 시작 파일의 실기기 실행은 이번에도 확인하지 못했습니다.

시각 구성 시험 중 AI 본문의 `section`이 Reveal의 세로 장표로 해석되는 문제를 발견해, 렌더링할 때 속성·내용을 유지한 `div`로 바꿨습니다. SVG 접근성·원호·점선·로컬 화살표 속성을 서버/브라우저 양쪽에서 지원하며, 스크립트·외부 URL·독립 CSS 애니메이션은 계속 거절합니다. 공통 차트에는 밝은/어두운 테마의 계열 색·축 라벨·격자 색을 적용했습니다.

동일한 7종 요청을 OpenAI 호환 API에도 실행했습니다. `openai/gpt-4.1-nano`는 보완 후 재시험에서도 0/7, `openai/gpt-4.1-mini`는 1/7(선 차트)만 형식 검증을 통과했습니다. 나머지는 금지 태그·속성·잘못된 효과 형식 등으로 거절됐고 적용하지 않았습니다. Codex CLI는 7/7 적용됐습니다. 이 수치는 이번 요청 묶음의 결과이며 일반적인 모델 성능 순위가 아닙니다. 작은 모델의 자유 화면 생성은 아직 안정적이라고 볼 수 없습니다. 보완 요청은 한 번으로 제한하고, 다시 실패하면 다른 모델/프로그램을 선택하도록 안내합니다.

재검사는 서버 실행 후 `/tests/browser/smoke.html`에서 **검사 실행**을 누릅니다. `?project=<AI 프로젝트 ID>`를 붙이면 해당 장표의 양쪽 테마 검사도 포함합니다. 결과 JSON을 저장할 수 있습니다. 실제 모델 생성 시험은 `python3 scripts/smoke_visual_scenarios.py --origin http://127.0.0.1:4176 --provider cli --tool codex`로 실행합니다. `--provider openai --model <모델>`도 지원하며 API 요금이 발생할 수 있어 `npm test`에는 포함하지 않습니다.

추가로 출력 예시와 효과 네 필드 제한을 요청에 포함해 nano를 같은 7종으로 재시험했습니다. 막대 차트만 적용돼 1/7이었고 나머지는 거절했습니다. 자유 화면 생성이 안정화됐다고 보지 않습니다. Codex로 생성한 시각 구성 7종의 자료는 9장·107.3초 MP4로 실제 녹화·변환했고 H.264·1920×1080·30fps를 확인했습니다.

### 이 키트로 제작한 사용법 영상

`examples/usage-demo/`의 11장·본문 9개를 같은 렌더러와 영상 내보내기로 제작했습니다. 실제 시나리오 입력·초안 편집·AI 요청·발표자·자막 설정 화면을 캡처해 포함했습니다. 표와 SVG 차트는 공통 Redwood 디자인을 사용합니다.

- Chrome에서 본문 9개×양쪽 테마 18/18, 기존 효과 33/33 검사 통과. 모든 장표를 화면으로 확인했고 마지막 장의 긴 제목과 부제·발표자 겹침은 제목을 줄여 수정했습니다.
- 편집 화면에서 AI 작성 본문을 불러오지 않아 미리보기가 실패하던 문제를 발표 화면과 같은 로더로 수정했습니다. 기존 AI 사진 장표를 편집 화면에서 다시 열어 실제 사진과 불러오기 완료 메시지를 확인했습니다. 오류 뒤 새 문서에서 초안 버튼이 비활성으로 남는 상태도 초기화합니다.
- 최종 11장 영상을 현재 공개 데모 탭으로 녹화·변환했습니다. 실제 MP4는 H.264·1920×1080·30fps·194.966초·3,719,165바이트입니다. 7초·90초·191초 프레임의 표지·어두운 표/차트·마지막 장과 한글 자막을 확인했습니다.
