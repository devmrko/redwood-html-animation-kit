# 베타 개선 순서

처음 사용하는 사람이 예제를 수정하고 발표·내보내기까지 완료하는 것을 목표로 합니다. 현재 공개 버전은 [v0.1.0-beta.1](releases/v0.1.0-beta.1.md)입니다. 우선 소수 사용자에게 제작·발표·내보내기를 요청하고, 아래 과제를 한 가지씩 보완합니다. 기존 문서 링크를 유지하기 위해 파일 경로는 그대로 사용합니다.

베타에서는 사용 환경(OS·브라우저·실행 방식), 재현 순서, 기대 결과와 실제 결과를 함께 수집합니다. 파일 더블클릭·Windows·독립적인 첫 사용 흐름은 아직 통과로 표시하지 않습니다. Ubuntu CI는 빌드·자동 검사·정적 검사를 수행하며 실제 발표 화면 검수는 별도로 진행합니다.

| --- | --- | --- | --- |
| 1 | 배포본 실행 안정화 | ZIP을 풀고 파일로 열어 본문·사진·증거·로컬 영상·발표자 창을 사용. 창 차단·종료·새로고침에서도 동작이나 실패 원인을 확인 | 진행 중. HTTP에서 재연결·종료 후 독립 조작·200% 확대까지 확인. 파일 실행·Windows 확인 필요 |
| 2 | AI 편집 신뢰성 | 선택 장표의 변경을 미리 보고 적용·취소·복원. 잘못된 생성 결과와 연결 실패에서 원본 보존 | 진행 중. 취소·초기 원본 차이·적용 전 파일 변경·합성 연결 실패·저장 중 닫기 검사. Codex·Claude·OCI 실제 제목/표 적용·복원 통과. 생성/저장 뒤 HTTP 응답 단절과 최신 상태 복구 확인. nano 표 품질·다른 OS·프로세스 종료 검증 남음 |

## 배포본 검수 방법

Python 3와 FFmpeg가 설치된 개발 환경에서 다음 명령으로 공개 합성 검증 자료를 만듭니다. 모델 호출과 API 키가 필요하지 않습니다. 출력 폴더가 이미 있으면 다른 경로를 지정합니다.

```sh
python3 tests/build_offline_fixture.py --output dist/offline-review
```

생성된 `offline-review.zip`은 실제 완성본 포장 함수를 사용합니다. `release/`는 그 ZIP만 푼 폴더이며, 표지·간지·사진과 세 단계 효과·어두운 표와 3초 영상·마지막 장을 포함합니다. 이 자료의 배포 허용 표시는 시험용 ZIP 생성을 위한 것으로, 실화면 검수가 끝났다는 뜻이 아닙니다.

파일 실행은 `release/index.html`을 더블클릭합니다. HTTP에서 같은 내장 코드를 확인하려면 다음처럼 **release 폴더만** 제공합니다. 발표 편집 API를 제공하지 않는 정적 서버입니다.

```sh
python3 -m http.server 4186 --bind 127.0.0.1 --directory dist/offline-review/release
```

`http://127.0.0.1:4186/index.html`을 열고 아래 순서를 파일 실행과 HTTP 실행에서 각각 확인합니다.

1. 표지·간지·본문·마지막 장과 사진을 확인합니다. 첫 장 이전과 마지막 장 다음 버튼이 비활성인지 확인합니다.
2. 사진 장표에서 다시 재생 → 일시정지 → 다음 단계 → 이전 단계를 조작합니다.
3. `Ctrl/Cmd+F`로 본문·발표 대본을 검색해 다른 장표로 이동합니다. `Ctrl/Cmd+R`은 브라우저 새로고침으로 남아야 합니다.
4. 증거 → 원본 확대로 이미지를 확인하고 Escape로 확대창과 목록을 차례로 닫습니다.
5. **발표 시작**으로 별도 청중 창을 엽니다. 청중 창에서 **발표자 보기**를 열어 장표·단계·재생·대본이 맞는지 확인합니다.
6. 발표자 창을 새로고침하고 청중 창의 현재 장표·재생 위치로 돌아오는지 확인합니다. 청중 창을 새로고침하면 같은 장표가 다시 재생되고, 기존 발표자 창이 재연결되어야 합니다. 청중 창을 닫은 뒤 발표자 창의 안내와 독립적인 장표 이동을 확인합니다.
7. 로컬 영상이 0초에서 3초로 진행하고 다른 장표로 이동하면 정지하는지 확인합니다. 인터넷이 필요한 YouTube는 로컬 영상 검수와 구분합니다.
8. 청중 창에서 발표자 보기를 다시 눌렀을 때 기존 창을 재사용하는지 확인합니다. 발표자 창을 닫고 다시 열었을 때도 연결되어야 합니다.
9. 발표자 화면을 200%로 확대해 도구 모음 아래에 미리보기, 그 아래에 스크롤 가능한 대본이 나오는지 확인하고 100%로 복원합니다.

실행 환경과 실제 결과는 [검증 범위](validation.md)에 기록합니다. HTTP에서 통과한 결과를 파일 실행이나 다른 운영체제의 통과로 간주하지 않습니다.
